# Ambient Dialogue

独立 AstrBot 插件，为现实群聊提供近期语境、现场口吻、明确记忆和自然插话。运行时不依赖 BotLife；群的机器人沿用 AstrBot 当前 Persona 和当前对话模型。

普通回复只增加本地整理和有界提示词，额外模型调用及网络请求均为 0。后台插话把“是否接话”和草稿合为一次当前模型调用，不设每小时、每日或累计消息数额度。没有新消息就不判断；@ 和正常回复优先，新消息、配置、Persona、模型或记忆变化会使旧草稿失效。

## 安装与启用

将本仓库作为 AstrBot 插件安装，要求 AstrBot 4.26.7（已验证临时内容持久化协议）及 Python 3.12+。在插件配置的“启用的群”添加精确群会话标识，QQ 官方账号填写 AppID；OneBot 填写机器人 QQ 号。默认仅采集验证、不注入、不插话。确认接收后关闭“仅采集验证”，再按需打开“自然插话”。

启用群的 AstrBot 配置方案应包含本插件，并移除 BotLife，同时关闭 AstrBot 内置 `provider_ltm_settings.active_reply.enable` 随机主动回复及 `group_icl_enable` 群聊历史注入。普通 @ 回复和 Ambient 插话使用同一份群语境，避免多条主动回复通道竞争。支持 QQ 官方 WebSocket、OneBot v11；只处理平台实际推送的消息，不调用历史拉取接口。QQ 未授权普通群消息或平台未推送时，无法旁听未 @ 的消息。

## 默认范围

| 内容 | 可调初始默认值 |
|---|---|
| 原话缓存 | 6 小时、最多 500 条/群；0 小时为仅内存 |
| 最近上下文 | 24 条 / 20 分钟 / 4500 字符 |
| 接话样本和近期纠正 | 2 小时、最多 16 个接话落点、每人最多 4 个、合计 1800 字符 |
| 记忆 / 统计 | 1500 / 500 字符 |
| 总动态包 | 8300 字符，含 JSON 元数据 |
| 记忆额度 | 每群 2 MiB；80% 压缩，目标 45% |
| 滚动摘要 / 明确偏好 | 800 字 / 每人 3 条 |
| 记忆整理 | 10 分钟一批，32 条，无模型调用 |
| 插话等待 / 判断间隔 / 冷却 | 8 / 30 / 30 秒，冷却可为 0 |
| 普通回复新鲜期 | 180 秒，生成前及发送前检查；可调至 30～240 秒 |

独立物理库 `groups/<平台+账号+原生群的哈希>/state.sqlite3` 使每群额度可以实际核算和回收。平台名、昵称、群名变化不用于认人；QQ 官方用稳定成员 OpenID，OneBot 用 QQ 号。模型只见本次的 u1/u2 别名、当前昵称和必要原话，不见稳定账号或群标识。普通闲聊不建长篇人物档案。

本插件对图片、语音、文件和视频只保留占位，不下载、识别或转写；AstrBot 自身的媒体预处理另受宿主配置控制。命令、自己的内容、附件、长文、重复文本、0/1 刷屏和持久格式命令不用于口吻样本；每位成员限制样本数，减少刷屏影响。

口吻学习先找“同一个人的相似场景”，再找同人或相似话题的原话；具体用词、语气词和短句节奏优先于抽象性格标签。只有原生引用 ID 或唯一完整引用文本能组成“前话 → 群友接法”，@ 和时间相邻不再被拼成回复案例。原生 ID 丢失不偷偷改用文本猜人；重复引用文本、截断预览、作者冲突和未来消息均不能配对。没有引用的短话仍可展示房间口吻，但明确标成独立样本。

样本整条纳入预算，保留原话和来源锚点，减少重复时间和昵称元数据；相关的两三条优先，贴切的常用短语可以借鉴，不要求每句话另造比喻或包袱。当前问题、对机器人的指令和机器人自己的回复不用于示范；机器人旧回复只进入现场语境与纠错。近期明确的“没和你说”“理解错了”等纠正会关联到已确认回复，问号、表情和沉默不作为评分。该过程只是本地选择短期证据，不训练模型、不自动改 Persona，也不新增长期记忆或逐条模型调用。

QQ 官方消息里的文字形式 @ 也会解析为接话对象，动态包不再携带其中的稳定 OpenID。明确 @ 别人的消息不触发自动插话；同一人的紧接着一句“那你……”附上短期对象线索，模型仍需判断语境。被明确拒绝插话时提示模型让出当前话头，不声称已经修改全群开关；不增加发言次数额度。

普通回复与插话统一使用 `build_pack`：当前消息、时间顺序的近期群聊、明确记忆、口吻样本、节奏统计。普通文字回复和插话都通过原生回执确认后写入同一窗口，附来源、时间及回复锚点；双方都能看到对方的实际发言。发送不明不重试、不冒充已送达。重复文本、无意义扣 0/1、内部编号泄漏在两条路径共用检查；明确的本次数学问答与一次性确认仍可回答 1。

动态包使用原生 `TextPart.mark_as_temp()`。启用接管后不再把 AstrBot 旧会话历史附到新请求，也不向该旧会话回写；旧历史仍留档，未删除。当前 Persona 和本轮工具仍可用；内置发送工具的本会话文字发送接到同一回执路径，其他会话维持原权限。文件等原生媒体发送没有可验证回执时不记为已确认。群内流式文字先收齐再检查，避免碎片绕过防复读。

普通回复在生成前、发送前检查原消息时间；过期直接放弃，不降级为主动重发。正常回复待处理时插话让位，新消息等变化仍会使插话草稿失效。AstrBot 4.26.7 的同人追问自动合并在本群运行实例上关闭，让每次请求都经过相同的上下文和时效检查。以上规则没有增加每小时、每日或累计发言数限制。

AstrBot 的旧会话、宿主日志、其他插件及部署备份不计入本插件每群额度；本插件不代管它们。上下文读取或注入失败时，接管群暂停本次回复，避免意外恢复旧历史。

## 明确记忆和纠错

成员实际触发回复或主动保存记忆时自动建立简短档案，昵称变化覆盖当前值；旁听普通群聊不建档，也不累计消息经验。个人事实仍须明确请求才进入候选。

自然请求例：`请记住我的偏好：饮料=白水`、`请记住我的边界：别说真名`、`请记录我的待办：买书`。只生成待整理候选，不把玩笑、转述或普通断言推断为档案。

群内 `/轻聊 状态` 只查看自己的记录；`/轻聊 记住 偏好 饮料=茶` 立即保存并纠正同键旧值；`/轻聊 删除 编号`、`/轻聊 完成 编号` 清理原记录、候选和摘要副本；`/轻聊 忘记我` 同时删除自己的 Ambient 原话缓存。支持称呼、偏好、事实、边界、承诺、待办，亦可使用相应英文类型。

压缩先清理过期原话，再去重、更新有来源的滚动事实摘要和清理普通旧档案。边界、承诺、未完成待办保留至明确删除、完成或到期。摘要与原记录删除在同一事务中，失败即回滚；完成后 VACUUM 回收物理空间，无向量索引和永久聊天流水。保护内容过多时不保证压到 45%，硬上限会暂停普通新记忆写入，聊天继续。

## 从 BotLife Light 迁移

详见 [迁移与回滚](docs/MIGRATION.md)。工具只生成配置建议，不静默改配置，也不删除源库。旧粗粒度关系转为 `interaction_note`；机器人状态和习惯仅导出供人工审阅；旧插话门禁不迁移，新进程须收到新消息才能插话。

## 验证

`python -m unittest discover -s tests -v` 运行不联网的行为测试。服务器原生 SDK 验证使用 `AMBIENT_NATIVE_TEST=1 python tests/test_native.py`，在 HTTP 边界拦截，不向 QQ 发消息。合成语料和本地性能报告只能证明相应测试范围；实际普通消息可见性和自然聊天质量须观察运行计数与真实群表现。
